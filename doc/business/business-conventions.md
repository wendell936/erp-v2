# 业务术语、编码与单据规范

## 术语

| 术语 | 统一含义 |
|---|---|
| 内部 SKU | 公司内部商品身份，不等同于 MSKU、ASIN、FNSKU 或供应商货号 |
| 配件 | 采购、入库并用于加工投料的商品角色 |
| 实体套装 | 按固定配方版本加工形成独立成品库存的销售商品 |
| 批次 | 有明确来源、数量和成本的库存追踪单位 |
| 实物库存 | 已实际入库且尚未出库的数量，包含已占用部分 |
| 已占用库存 | 已分配给业务需求、不能再向其他需求承诺的库存 |
| 可用库存 | 满足可用条件的实物库存减去有效占用，不包含在途或未质检合格数量 |
| 在途 | 已实际发运、尚未按相应环节接收的数量；国内和 FBA 分开展示 |
| 销售成本 | 销售实际消费的成品成本，不再次消费其组件成本 |
| 利润与现金 | 利润按收入费用口径计算；现金按实际可用余额和收付款计算 |

不同仓库、质量状态及单位的数量不直接混加；跨阶段汇总明确去重关系。退货及成本处理遵循需求基线，不由术语表另行扩展。

## 编码与状态

- 技术主键与业务编码分离；业务编码不可作为可随意修改的关联键。
- SKU 的具体词典由真实首组商品确认，不把测试编码固化为正式规则。
- 单据号由服务端生成，数据库唯一约束兜底，不用“查询最大值加一”分配编号。编号不要求无断号，不复用已作废编号。
- 持久化状态使用稳定编码和对应枚举或字典，界面显示业务名称，不散落魔法数字或以显示文字驱动业务。
- 商品单位、费用计费单位、币种使用统一字典或既有标准字段。换算需有明确基数和精度。

## 单据生命周期与纠错

| 阶段 | 操作边界 |
|---|---|
| 草稿 | 可修改和删除，前提是尚无下游引用或业务影响 |
| 已确认 | 固定已确认的关键字段及快照；未执行部分的变更须评估下游影响并留痕 |
| 部分执行 | 按实际执行数量保留进度，只对剩余可执行部分办理后续操作 |
| 已完成 | 不直接改写已发生的数量、金额、来源和成本事实 |
| 取消或纠错 | 未执行部分可按规则取消；已执行部分用关联的退回、冲销或调整记录处理 |

- 上表是设计边界，不强制所有业务共用一个状态枚举。采购、收货、加工、发货分别定义合法转换和前置条件。
- 每类单据开发前明确字段可修改矩阵、允许操作、数量上限、下游依赖及纠错入口。采购状态、付款状态、物流状态分开管理。
- 确认、执行、取消须在服务端重新检查当前状态，通过事务及条件更新或锁控制并发；操作结果与业务流水保持一致。
- 已发生库存、费用或资金影响的记录不得直接物理删除，不以修改库存余额或原金额代替纠错。
- 具体冲销顺序、跨期处理及费用责任不明确时按需求流程确认，不自动推断。
