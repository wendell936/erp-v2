# 商品档案、配方映射与参考测算设计

2026-10-13，P1-01.d。业务规则唯一来源为[需求基线](../requirements/requirements-checklist.md)商品-01～08、供应-01/02及测算-01～05。本文描述本轮确认后的设计影响和建议结构，不代表相关表、接口或页面已经实现。

同日[整体审查](../testing/project-consistency-review.md)确认现有架构和上述业务方向可保留，但已有会话撤权、文件权限、敏感日志及编号命名空间问题须优先关闭；商品身份规则已明确不等于当前安全/编号实现已经足够稳妥，后续推进按任务台账的审查修复前置执行。

## 当前实现与设计结论

已交付产品类型、内部持久编号、供应商基础资料和按日汇率；完整商品档案、配方、平台映射、多报价和物流测算尚未实现。保留现有模块化架构，不新增服务或中间件；复用现有分页、权限、审计、精确十进制与事务能力。

用户本轮进一步确认了原SKU保留独立库存及业务、组合映射独立成品后展开组件、ADF=A+D+F、参考汇率按不晚于测算日期的最近日期取值。此前针对这四点的待确认标记解除；报价单位、包装实重、计费进位和尾程报价细则仍待确认。

## 关系与职责

| 对象/关系 | 建议职责与约束 | 实现状态 |
|---|---|---|
| 产品类型 | 名称、类型码、关键词；不决定SKU库存或组合归属 | 已实现 |
| 编号记录 | 不可变SKU业务编码、技术ID、主/变体序号及请求幂等 | 已实现；见[编号契约](product-types-and-sku-numbering.md) |
| 商品SKU | 独立身份、名称、计量单位、单品/组合属性、状态、规格及参考链接；关联一条编号记录 | 待实现 |
| 编码父子关系 | 记录变体由哪个原SKU派生；原SKU和新变体各有业务身份及库存归属 | 编号归属已实现，商品关联待实现 |
| 供应商报价 | SKU与供应商的多报价关系，保留原币、计价单位、货号、交期、来源及版本/确认信息；默认供应商单独维护 | 供应商资料已实现，报价待实现 |
| 组合配方版本/行 | 成品SKU关联所选组件SKU、每套数量和单位，可复用组件；禁止自身/循环引用 | 待实现 |
| 平台映射 | Seller SKU/MSKU关联一个内部单品或成品SKU；一个内部SKU可被多个MSKU引用；组合展开该成品的配方 | 待实现 |
| 商品物流参考测算 | 销售包装、实重、空/海报价、参考汇率和解释性结果；明确参考状态 | 待实现 |

“组件”是SKU被配方使用的角色，不是与“可独立使用的单品”互斥的身份。某SKU可以在自己的业务中使用，又被不同组合引用。编码父子关系不生成配方，不强制组件属于同一编码父级；变体SKU的库存不能并入原SKU合计后当成另一份可用库存。

组合示意：MSKU-ABC → 成品SKU-ABC → 配方v1的A、B、C；MSKU-ADF → 成品SKU-ADF → 配方v1的A、D、F。A只有一个内部身份，可参与两个组合；成品ABC和ADF各有自己的库存及成本来源。示意名称均为业务示例，不生成正式字典、SKU或MSKU。

平台映射页展开组件用于理解销售内容、报价与配方来源；实体加工先消耗组件形成成品，销售再消费成品成本。不能因为页面展开了配件，就让销售同时扣减组件和成品成本。历史单据引用当时的配方、报价、图片、映射及成本事实，后续修订不得改写旧事实。

## 商品与报价页面

建议原SKU和变体均作为可查询的独立商品记录，列表可按原SKU展开变体，但采购/库存选择落到具体SKU。新增变体保留原编号，不触发库存转移；原有库存继续留在原SKU。创建商品与分配编号仍需同一个READ_COMMITTED事务，失败共同回滚，不暴露独立领号操作。

每个实际配件/变体维护自己的价格、规格、供应商和多报价；组合页面显示成品身份、版本配方、组件及用量、逐行报价和可追溯合计，不要求业务人员在各MSKU下重复维护相同组件。

非组合配件的“采购成本”按业务用语对应其单套报价；组合的采购报价合计为各组件的用量×所选单位报价之和。计算前必须明确单套内数量、SKU计量单位及换算；不存在已确认换算时不能直接相乘。跨币种须先统一币种并展示换算依据，不能把CNY和USD数值直接相加。

建议界面用“单套采购报价”“组件报价合计”“实际库存成本”区分含义；组件报价合计不是包含加工、包材、国内运费和实际头程的最终成品成本。默认供应商已确认，但同供应商有多份报价时选哪一份、报价含税/含运范围、价格精度及跨币种参考日期仍待确认，不擅自选最低价或最新更新时间。

## 包装与物流参考测算

默认包装字段指最终销售包装，长宽高以cm、实重以kg参与测算；不合并商品本体、销售包装和实际出货箱规。组合销售包装不能自动由组件长宽高或重量相加生成；组合与组件的包装记录归属、实重是否含销售包装、更新是否联动仍待确认。

空运与海运独立计算：销售包装体积÷5000或6000得到体积重；体积重严格大于实重时为抛货，计费重量取较大者，相等不判为抛货。国内报价以CNY/kg保留，乘计费kg后为CNY参考费用，再除“1 USD=X CNY”的汇率得到USD。不得把国内CNY/kg报价当成USD/kg再换算一次。

测算日期由业务明确选择，参考汇率选择满足`rateDate <= estimateDate`的最大日期记录，不是最后编辑的记录，不使用未来日期。展示实际汇率日期、值及版本；没有候选汇率时显示待补。既有按日精确换算接口保持原语义，后续另加清晰命名的参考取值能力和对应权限/测试，不放宽实际确认接口。

建议测算结果关联或返回输入的包装资料、来源及确认时间、报价来源/日期、测算日期、选定汇率、两种体积重、抛货判定、计费重量和USD参考结果，以支持人工核对。是否保存可重新打开的独立测算记录尚未确认，本轮不预建报价流水或财务事实。参考尾程以USD表达，报价来源、单位和自动算法未确认；不接入未经确认的Amazon费率表。

精确十进制参与体积、重量和费用计算，禁止以界面显示的0.18/0.15kg回算。重量是否向上进位、最小计费重、USD结果精度/舍入、附加费/阶梯价仍需确认；不能从样例中发明规则。已确认人民币按分HALF_UP及汇率最多8位小数继续适用，不自动推定美元也采用同一规则。

## 验收设计与推进条件

以下是后续功能验收条件，本轮仅校核文档和算例，没有执行这些业务功能测试。

| 场景 | 后续预期 |
|---|---|
| 原SKU新增变体 | 原编码、库存和历史单据不变，新编码追加后缀，新变体独立记账；失败不留下商品或孤立编号 |
| 一个内部SKU多个MSKU | 查询各映射可回到同一身份，销售分别归属，不因多映射重复结转成本 |
| 组合共享组件 | ABC与ADF共享A，配方分别固定组成及用量；共享不重复承诺库存，销售不重复扣组件成本 |
| 变更组件报价/配方 | 当前参考合计可按重新选定资料计算，旧采购单和旧成品批次保留当时事实 |
| 缺报价或混币种 | 展示未完整/待补，不以0冒充缺失，不做无依据的跨币种求和 |
| 头程样例 | 910.8cm³；空运0.18216kg、海运0.1518kg，两者计费均0.24kg；费用分别14.4/6.92和4.08/6.92USD |
| 抛货及相等边界 | 体积重大时取体积重，实重大时取实重，相等取相同重量且非抛货；具体显示/计费进位按待确认规则 |
| 最近参考汇率 | 有测算日前日及未来记录时选前日、显示日期；有当日记录时选当日；仅有未来记录时提示待补；旧日期后来被编辑不改变日期排序 |
| 实际费用确认 | 指定日缺汇率仍提示待补，不借用参考测算的最近汇率；后续修改不重算旧事实 |

商品身份/原SKU/变体/成品映射的概念设计已明确，可继续细化商品基础字段与关系；金额字段和计算在报价单位/精度确认前不落地。具体台账拆分见P1-01.c/e/f、P1-02.b及P1-25，正式资料在实际建档与联调时补充，不用示例填充。
