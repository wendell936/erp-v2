## 范围与字段

产品类型是平级字典，维护类型码、名称、关键词、备注及启停。类型码为1～40个ASCII英文字母或数字，禁止连字符/下划线/空白/中文，连字符仅用于SKU层级分隔，名称必填最多200字，关键词和备注最多500字；首尾空白去除，类型码保留输入拼写，大小写不敏感唯一。关键词是自由文本搜索字段，不建立多级分类或独立标签系统。未预置工作簿示例或正式词典。

类型一旦成功分配过编号，类型码不能修改；名称、关键词和备注仍可修改。停用保留资料和既有编号，阻止新增主编号及变体编号，原请求重试仍返回已存在记录。不提供删除、降低计数或重置入口。

类型 ID、版本、编号 ID 和计数在 HTTP JSON 中使用十进制字符串。时间点沿用项目 UTC DATETIME(3) 处理器和接口时间规则，业务编码与数据库主键分离。

## 类型接口与权限

| 方法与路径 | 权限 | 行为 |
|---|---|---|
| GET `/erp/product-type/list` | `erp:productType:list` | `typeName` 搜索名称/类型码/关键词，`status` 为0启用或1停用 |
| GET `/erp/product-type/{id}` | `erp:productType:query` | 返回当前资料，未知 ID 报错 |
| GET `/erp/product-type/{id}/changes` | `erp:productType:query` | 分页查询人员、时间、原因和操作 |
| POST `/erp/product-type` | `erp:productType:add` | UUID `requestId` 幂等创建，默认启用、版本和计数均为0 |
| PUT `/erp/product-type/{id}` | `erp:productType:edit` | 携带当前 `version` 和非空 `reason`，条件更新并追加审计 |
| PUT `/erp/product-type/{id}/status` | `erp:productType:status` | 携带 `status/version/reason`，条件更新并追加审计 |

列表默认每页10条、最多100条，默认 ID 倒序，客户端排序仍追加唯一 ID；变更记录同样分页。管理员和操作角色有全部上述权限，按已确认公司数据范围查询。2026-10-13撤销只读业务账号需求，历史无写权限夹具仅用于负例回归。

创建请求 UUID 统一小写。相同请求标识、规范化字段及操作人返回同一记录；该类型后来编辑过时返回当前资料。其他内容或操作人复用请求键、其他请求使用已有类型码均拒绝。修改与启停采用版本条件更新；过期版本须刷新核对，不自动覆盖。资料和审计同事务，审计失败全部回滚。前端保留保存失败后的填写内容和创建请求键，重试不另生成请求键。

## 内部编号服务

`SkuNumberService.allocateMain(typeId, requestId)` 分配 `类型码-序号`；`allocateVariant(mainNumberId, requestId)` 分配 `主编码-变体序号`。主序号按类型从1递增，变体序号按主编号从1递增，不补零、不使用列表行号或 `MAX+1`。变体不能再作为主编号。序号使用正 BIGINT，达到上限报错，不溢出。

服务仅供后续商品业务调用，没有独立 HTTP 分配接口或用户领号页面，也不创建商品、Listing、库存和成本。编号表长期保留，未来解除商品引用不得删除编号记录或降低计数。2026-10-13用户确认单规格新增变体后原SKU保留自己的库存及业务，新变体独立；商品关联及新增变体流程仍待实现，删除业务入口及历史引用保护另按相应任务处理。

每次请求先查持久请求键，再锁类型行并重新查键；变体统一在类型锁之后锁主编号行。再次查键显式刷新 MyBatis 一级缓存，避免复用首次查询的空结果。计数递增与不可变编号插入同事务，失败同时回滚。相同 UUID 必须匹配类型、主编号范围和操作人；全局 SKU 唯一约束兜底，不自动改码或跳号。类型新增/编辑与数据库仅允许英文字母数字，从类型空间排除主/变体交叉。服务对未升级库中的旧格式拒绝新领号，已存在同请求编号仍返回原值；不改旧SKU，不用跳号恢复。

事务使用 `REQUIRED + READ_COMMITTED`，不会独立提交领号。后续商品保存事务必须显式使用 READ_COMMITTED 并将编号分配纳入同一事务；服务检测外层实际隔离级别，不接受默认 REPEATABLE_READ 的旧快照，也不以 REQUIRES_NEW 脱离业务回滚。业务调用方负责商品操作权限、参数校验及持久化关联，编号服务要求认证操作人。

## 数据库升级与恢复

唯一脚本目录见[数据库规范](database-migrations.md)。前置版本 V2026101105，按顺序执行：

1. [V2026101201](../../erp-front/ruoyi-admin/src/main/resources/db/migration/V2026101201__product_types_and_sku_numbers.sql)：新增类型、类型变更审计、SKU 编号三表，以及权限。类型和 SKU 各有大小写不敏感唯一键；请求键、审计版本及变体序号有唯一约束，外键保护类型和同类型主编号引用。
2. [V2026101202](../../erp-front/ruoyi-admin/src/main/resources/db/migration/V2026101202__product_type_page_menu.sql)：将已有类型权限归入 ERP 产品类型菜单。该历史脚本按当时三角色矩阵向已有有效角色授权，不创建正式业务账号，不改写已执行迁移；当前角色范围以2026-10-13两角色矩阵为准。

3. [V2026101401](../../erp-front/ruoyi-admin/src/main/resources/db/migration/V2026101401__product_type_alphanumeric_codes.sql)：单条ALTER替换类型码CHECK，禁止连字符；原9份迁移不改。升级前暂停类型/编号写入并备份，执行脚本注释中的非法类型码预检。存在旧不合法类型时阻断发布，不自动清理、改码或重编号；核对业务引用后另行授权处理，或恢复备份。已用类型无自动改码通道，不承诺自动兼容旧冲突资料。

升级不导入示例、不触及资金和库存；合法旧类型/编号/计数及审计不变。应用回退时保留新增表、历史编号和迁移记录；旧应用回退时仍保留新的严格约束，旧版提交含连字符类型会失败，不能撤掉约束继续写入。菜单若需暂时隐藏，另行评审权限/菜单前向脚本，不删除历史数据。不把 MySQL DDL 视为事务自动回滚；失败停止部署，检查实际表与 Flyway 历史，再采用已评审前向修复或备份恢复，不自动 repair/clean。
