# 需求与验收规范

适用日期：2026-10-09。业务范围以 [业务需求基线](requirements-checklist.md) 为准。

## 需求描述

每项开发任务引用已有需求编号；新增需求分配不重复的编号。简单任务可直接在任务说明中记录，跨模块需求在本目录建立对应主题文档，不为每次修改创建独立文档。

开发前明确：

| 项目 | 必需内容 |
|---|---|
| 目标与范围 | 使用人员、触发场景、解决的问题、范围外事项 |
| 前置条件 | 权限、基础资料、单据状态及来源数据 |
| 输入输出 | 字段、单位、币种、必填条件和展示结果 |
| 业务影响 | 数量、库存、成本、费用、资金及关联单据的变化 |
| 异常与并发 | 缺资料、权限不足、状态冲突、重复提交和执行失败 |
| 验收条件 | 可复现输入、执行步骤、明确的预期结果 |
| 待确认项 | 问题、影响范围及确认结果；不得伪装成已确定规则 |

## 需求变更

- 状态按待澄清、已确认、开发中、待验收、已验收管理；实际状态保留在任务或主题文档中，不把需求基线当作完成清单。
- 变更先评估接口、数据库、历史单据、权限、成本与验收用例的影响，再更新同一主题文档。
- 涉及金额、库存、权限和不可逆行为的未决规则，在相关实现前确认；不影响的独立工作继续推进。
- 技术实现方案放入开发或架构文档，需求文档主要描述业务行为。

## 验收与完成

验收至少包括正常流程、关键边界、无权限、重复执行和失败恢复；核心业务验证数量金额及来源追溯。具体回归样例见 [首个业务闭环](../testing/first-business-loop.md)。

完成意味着：实现符合确认需求；相关构建与必要测试通过；数据库脚本、权限配置、文档同步；没有遗留临时调试代码；交付说明列出实际验证、未验证项和待办。仅页面可操作不视为核心业务完成。
