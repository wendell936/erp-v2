# 数据库迁移工具决策

日期：2026-10-11。关联 P0-09～12、P0-14；实际结果见[执行记录](../development/execution-journal.md)。

采用 Spring Boot 4.1.0 BOM 管理的 Flyway 12.4.0，入口模块引入 `spring-boot-starter-flyway`、`flyway-mysql`，沿用 MySQL 驱动、Druid 和 MyBatis，不升级框架。收益是复用版本排序、校验值、迁移历史和数据库锁，避免自建执行器。候选制品 Flyway parent POM 声明 Apache-2.0；当前仅使用开源 SQL 迁移、校验及显式基线功能。完整依赖漏洞扫描尚未完成，不把编译或 BOM 收录当作安全审计。

## 来源与装配

- 唯一脚本目录为 `erp-front/ruoyi-admin/src/main/resources/db/migration/`，加载路径为 `classpath:db/migration`。原若依、Quartz SQL 已移动到 V2026041701、V2026041702，移除全部初始化删表语句，不维护第二份 SQL。增量 `V2026101101__user_unlock_permission.sql` 注册用户解锁按钮权限，仅分配给有效管理员角色。
- 基线保留若依原种子数据，包括演示账号、菜单和任务，仅用于隔离开发测试。正式启用前须按权限、账号和调度任务台账处理演示内容、更换初始凭据，不能直接当作生产配置。
- 迁移默认关闭，显式设置 `ERP_DB_MIGRATION_ENABLED=true` 才启动迁移。开发测试允许此方式；生产执行仍遵循授权、备份、预检流程。运行账号和迁移账号权限须在部署时分离，当前未提供生产执行入口。
- `DatabaseMigrationConfig` 固定使用物理 `masterDataSource`，不受业务动态数据源选择影响。MyBatis 会话工厂声明依赖数据库初始化，迁移失败不创建业务会话。
- 禁止自动 baseline、clean 和乱序执行，启用名称、校验值验证，并清空默认忽略未来版本的模式。环境参数不能绕过这些约束。

## 空库与已有库

空库顺序执行两个基线及后续增量，历史表保存版本和校验值。再次迁移不重放 SQL、不重置数据。MySQL 迁移使用 Flyway 的数据库锁；多进程竞争和中断恢复仍须结合实际部署演练。

未知非空库直接阻断。已有若依库接管必须先备份，对照两个基线核对表、列、索引、约束、字符集及 Quartz 表大小写等结构，经负责人员确认后显式执行 `baselineVersion("2026041702").baseline()`。该 API 只写标记，不会比对或修复结构。测试中的精确已知基线不能用于证明真实既有库可接管；未获批前不提供自动接管脚本。接管后仅运行更高版本脚本，保留已有账号和配置。

## 失败与恢复

MySQL DDL 可能部分提交。任何失败停止后续迁移，保留日志、失败历史及数据库现场；重启仍阻断。禁止自动 repair、删除历史或修改成功脚本。

测试演练使用真实 mysqldump 备份，失败后恢复临时库备份，核对迁移历史和合成记录，随后执行修正后的未成功迁移。生产恢复需另行授权并评估备份后写入，不能照搬测试中的删建数据库。通常优先使用审核后的前向修复；确需 repair 时，必须先核对部分 DDL、恢复结构一致性并保留审计，不以 repair 消除错误提示冒充恢复。

校验值变化、失败标记、数据库存在当前代码未包含的未来迁移均阻断。应用回退不等于数据库回退，需要兼容的新代码或授权恢复。

## 验证入口与限制

[隔离测试脚本](../../scripts/test-database-migrations.sh)创建独立 MySQL 8.4 和 Redis 7.4 容器，只绑定 loopback，随机生成凭据，执行 Failsafe 的 `migration-it` profile，结束后删除本轮容器。测试库名随机生成，不访问业务库；TLS 关闭仅用于该临时 loopback 实例。

用例覆盖 Boot/Flyway 与 Druid/MyBatis 装配、空库初始化、再次运行、显式基线接管、增量、失败阻断、校验值及未来版本、真实备份恢复；完整应用还覆盖 HTTP 登录、真实 Redis TTL、大小写账号锁定、并发计数、解锁鉴权及状态保留。实际 MySQL 为 8.4.11、JDK 为 21；Java 17、真实既有库接管、浏览器页面、生产备份性能与恢复目标、账号权限分离及多进程并发部署尚未验收。
